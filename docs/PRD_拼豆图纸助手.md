## 二、产品概述

### 2.1 背景与目标

**背景：**

拼豆（Perler Beads / Fuse Beads）是一种将小型塑料珠子在模板板上排列后熨烫成型的手工艺品。爱好者需要将参考图片转换为与拼豆色板匹配的像素化图纸，目前主要依赖以下方式：

- 手动在格纸上逐格填色，耗时且容易出错
- 使用 PC 端软件（如 BeadTool），操作不便，无法随时随地使用
- 用通用像素画 APP 手动调色，不支持拼豆品牌色板匹配

这导致从"灵感图片"到"可执行图纸"的过程低效、门槛高，尤其对新手不友好。此外，立体拼豆（3D Perler Beads）需要将立体造型拆解为多个平面零件并设计拼接卡槽，目前完全依赖经验，缺乏辅助工具。

**Goals（目标）：**

1. 让用户在手机上 3 分钟内完成一张图片到拼豆图纸的转换
2. 转换结果的颜色匹配准确率达到人眼可接受水平（与实际拼豆颜色肉眼无明显色差）
3. V1 上线 3 个月内累计下载量达到 10,000+
4. 付费转化率达到 5% 以上
5. 成为拼豆爱好者首选的移动端图纸工具

**Non-Goals（非目标）：**

1. **不做社区功能**：社区涉及内容审核、UGC 管理、社交关系链等大量复杂模块，当前阶段聚焦工具能力本身。用户之间的图纸流转通过分享链接实现。
2. **不做线上豆子商城/购买引导**：不做电商，不引流到任何豆子销售平台，保持工具中立性。
3. **不支持离线使用**：项目数据云端存储，避免本地/云端数据同步的复杂性。
4. **不做 PC/Web 端**：聚焦移动端体验，PC 需求通过导出 PDF 打印满足。
5. **不做异形板支持**：当前仅支持方形板（含拼接），六边形板、心形板等异形板留给后续版本。

### 2.2 产品定位

为拼豆爱好者提供**图片一键转图纸**的移动端工具，支持多品牌色板精确匹配、实时预览编辑和图纸导出，并逐步拓展到立体拼豆拆件辅助。

### 2.3 目标用户

| 用户角色 | 描述 | 核心诉求 | 使用频率 |
|---------|------|---------|---------|
| 拼豆新手 | 刚接触拼豆的爱好者，主要做简单平面作品 | 快速把喜欢的图片变成图纸，降低入门门槛 | 每周 1-3 次 |
| 拼豆进阶玩家 | 有经验的爱好者，追求高还原度，会做多板大图 | 精确色彩匹配、高级调色、多板拼接 | 每周 3-5 次 |
| 立体拼豆玩家 | 制作 3D 立体拼豆作品的高阶用户 | 立体造型拆件方案、卡槽设计辅助 | 每周 1-2 次 |

## 四、功能需求

### V1 — MVP

#### 4.1 用户注册与登录

**用户故事：** 作为用户，我希望用常用账号快速登录，以便保存我的项目数据。

**功能描述：**
- 支持手机号、微信、Apple ID、邮箱、Google 账号登录
- 首次使用第三方登录自动注册
- 支持账号合并：当用户用不同方式登录但实际是同一人时（如手机号注册后又用微信登录），提供账号合并入口
- 购买记录与账号绑定，换设备后登录同一账号自动恢复购买状态

**业务规则：**
1. 账号唯一标识以手机号或邮箱为主键
2. 账号合并时，保留项目数量较多的一方数据，另一方数据合入
3. 合并后原账号不可再单独登录
4. 若合并后项目总数超过免费槽位上限，已有项目均保留可查看，但不可新建直到删到上限以下或升级付费

**验收标准：**
- Given 用户未注册，When 用手机号+验证码登录，Then 自动完成注册并进入主页
- Given 用户已有手机号账号，When 用微信登录时检测到相同手机号，Then 提示是否合并账号
- Given 用户在设备 A 购买了高级版，When 在设备 B 用同一账号登录，Then 自动恢复付费状态

**异常处理：**

| 异常场景 | 处理方式 | 提示文案 |
|---------|---------|---------|
| 验证码发送失败 | 提示重试 | "验证码发送失败，请检查网络后重试" |
| 第三方登录授权失败 | 提示重试或换方式 | "授权失败，请重试或使用其他方式登录" |
| 账号合并冲突（两边都有付费记录） | 合并后保留付费状态 | — |

**优先级：** P0

---

#### 4.2 图片上传与预处理

**用户故事：** 作为用户，我希望从相册选图或直接拍照，快速开始制作图纸。

**功能描述：**
- 支持从手机相册选择图片或调用摄像头拍照
- 支持格式：PNG、JPG/JPEG、BMP、WebP
- 上传后系统自动预处理：
  - 过大图片（超过 4096×4096）自动压缩至合理尺寸，用户无感知
  - 过小图片（低于 50×50）提示"图片分辨率较低，转换效果可能不理想"，但允许继续
  - 不支持的格式明确提示支持的格式列表

**业务规则：**
1. 上传成功后自动进入板子选择界面
2. 图片存储在云端，与项目绑定

**验收标准：**
- Given 用户选择一张 8000×6000 的 JPG 照片，When 上传完成，Then 系统自动压缩，用户无感知地进入板子选择界面
- Given 用户选择一张 30×30 的小图，When 上传完成，Then 系统弹出提示"图片分辨率较低，转换效果可能不理想"，用户点击"继续"后正常进入
- Given 用户选择一个 GIF 文件，When 检测到格式不支持，Then 提示"暂不支持此格式，请选择 PNG、JPG、BMP 或 WebP 格式的图片"

**优先级：** P0

---

#### 4.3 板子选择与图片调整

**用户故事：** 作为用户，我希望先选好要用的拼豆板规格，然后调整图片在板子上的大小和位置。

**功能描述：**
- 板子规格选择：
  - 预设常用尺寸：29×29（小板）、58×58（大板）
  - 自定义尺寸：用户输入宽×高格数
  - 多板拼接：选择 N×M 块板拼接（如 2×2 块 29×29 板 = 58×58 区域）
- 图片调整：
  - 默认自适应板子大小（图片缩放至完整填充板子区域）
  - 支持手动缩放（双指捏合）和平移（拖拽），调整图片在板子上的覆盖范围
  - 实时显示当前图片覆盖的格数

**业务规则：**
1. 先选板子，后调图（流程顺序固定）
2. 默认板子尺寸为 58×58
3. 自定义尺寸上限为 200×200（超过此尺寸渲染性能和实际拼豆可行性下降）
4. 多板拼接时，系统自动在对应位置标注板子分界线

**验收标准：**
- Given 用户选择 58×58 板子并上传图片，When 进入调整界面，Then 图片自动缩放填满 58×58 网格区域
- Given 用户选择自定义尺寸并输入 300×300，When 确认，Then 提示"尺寸上限为 200×200，请调整"
- Given 用户选择 2×3 块 29×29 拼接，When 进入调整界面，Then 显示 58×87 的网格区域并标注板间分界线

**优先级：** P0

---

#### 4.4 颜色匹配与转换

**用户故事：** 作为用户，我希望系统自动将图片每个像素匹配到最接近的拼豆颜色，生成可执行的图纸。

**功能描述：**
- 图片经过像素化（缩放到板子网格尺寸）后，每个格子的颜色映射到所选色板中最接近的拼豆颜色
- 颜色匹配算法在 CIELAB 色彩空间中计算，使用 CIEDE2000 色差公式（更符合人眼感知）
- 转换完成后显示：
  - 图纸预览（每格填充匹配到的拼豆颜色）
  - 每格显示对应的豆子颜色编号
  - 用量统计：按颜色编号列出每种颜色所需豆子数量

**业务规则：**
1. 默认使用 Artkal 5mm 色板
2. 转换过程实时进行，用户调整图片时即时更新预览
3. 用量统计按数量从多到少排序

**验收标准：**
- Given 用户完成图片调整，When 系统执行颜色匹配，Then 每个格子显示匹配到的拼豆颜色且肉眼与原图无明显色差
- Given 一张 58×58 的图纸，When 查看用量统计，Then 所有颜色数量之和 = 58×58 = 3364

**优先级：** P0

---

#### 4.5 实时预览

**用户故事：** 作为用户，我希望在调整参数时实时看到图纸效果变化，快速做出决策。

**功能描述：**
- 所有调整操作（图片缩放/平移、色板切换、格子编辑、抖动参数等）即时反映到预览画面
- 预览支持缩放和拖拽浏览（针对大图纸）
- 支持预览模式切换：
  - 色块模式：每格填充纯色（默认）
  - 圆点模式：每格中心画圆点，模拟真实拼豆效果
  - 编号模式：每格显示颜色编号，适合对照图纸拼豆
- 支持对比查看：左右对比原图与转换结果

**业务规则：**
1. 预览渲染延迟不超过 200ms（用户操作到画面更新）
2. 大图纸（>100×100）可适当降低预览精度以保证流畅度

**验收标准：**
- Given 用户在 58×58 图纸上切换色板，When 切换完成，Then 预览在 200ms 内更新
- Given 用户切换到编号模式，When 缩放到足够大，Then 每格清晰显示颜色编号文字
- Given 用户点击"对比"按钮，When 进入对比模式，Then 左侧显示原图、右侧显示转换结果，可同步缩放

**优先级：** P0

---

#### 4.6 基础手动编辑

**用户故事：** 作为用户，我希望手动修改个别格子的颜色，微调图纸效果。

**功能描述：**
- 点击图纸上的任意格子，弹出当前色板的颜色选择器
- 选择颜色后，该格子颜色更新，用量统计实时重算
- 支持撤销/重做操作

**业务规则：**
1. 颜色选择器仅显示当前所选色板中的颜色
2. 如果启用了"我的豆库"筛选，选择器中标注用户没有的颜色（灰色展示但仍可选择）
3. 撤销/重做支持最近 50 步操作

**验收标准：**
- Given 用户点击图纸上一个格子，When 从色板选择新颜色，Then 格子颜色更新、用量统计实时变化
- Given 用户连续编辑 3 个格子，When 点击撤销 2 次，Then 回退到编辑第 1 个格子后的状态

**优先级：** P0

---

#### 4.7 多品牌色板切换

**用户故事：** 作为用户，我希望切换到我使用的拼豆品牌色板，确保图纸上的颜色编号与实际豆子一致。

**功能描述：**
- 内置主流品牌色板数据：
  - Artkal（H 系列 5mm 硬豆、S 系列 5mm 软豆、C 系列 2.6mm 等）
  - Hama（基础色、扩展色等系列）
  - Perler（标准色系列）
  - 国产品牌（根据市场调研补充）
- 色板数据包含：颜色编号、颜色名称、RGB 值、是否停产
- 支持随时切换色板，切换后图纸自动重新匹配颜色
- 停产颜色在色板中标注，匹配时默认跳过（用户可手动选择启用）

**业务规则：**
1. 色板数据作为 APP 内置资源，随版本更新
2. 切换色板后，所有格子重新执行颜色匹配
3. 手动编辑过的格子，切换色板后也重新匹配（编辑记录清空，切换前需提示用户确认）

**验收标准：**
- Given 用户当前使用 Artkal H 系列色板，When 切换到 Hama 色板，Then 系统提示"切换色板将重新匹配所有颜色，手动编辑将重置，是否继续？"，确认后所有格子重新匹配
- Given 色板中有停产颜色，When 查看色板列表，Then 停产颜色标注"已停产"标记

**优先级：** P0

---

#### 4.8 我的豆库

**用户故事：** 作为用户，我希望标记我实际拥有的豆子颜色，让系统只用我有的颜色来匹配。

**功能描述：**
- 选择一个品牌色板后，默认展示该色板全部颜色（视为用户全部拥有）
- 用户可以手动取消勾选没有的颜色
- 启用"仅用我的豆库匹配"开关后，颜色匹配时只在用户拥有的颜色范围内进行
- 豆库数据按品牌+系列分别管理，跟随账号存储

**业务规则：**
1. 豆库筛选影响自动匹配结果，但不限制手动编辑（手动编辑时可选择豆库外的颜色）
2. 豆库外的颜色在选择器中灰色显示并标注"未拥有"
3. 如果豆库中颜色过少（<10 种），匹配前提示"当前豆库颜色较少，图纸效果可能不理想"

**验收标准：**
- Given 用户在 Artkal H 系列中取消 20 种颜色并开启豆库筛选，When 重新匹配，Then 图纸仅使用剩余颜色，用量统计中不出现被取消的颜色
- Given 用户豆库中只有 5 种颜色，When 开启豆库筛选，Then 提示"当前豆库颜色较少（5 种），图纸效果可能不理想，是否继续？"

**优先级：** P0

---

#### 4.9 多板拼接

**用户故事：** 作为用户，我希望制作超过单板大小的图纸，系统帮我标注每块板的区域和分界线。

**功能描述：**
- 在板子选择阶段设置拼接方式（N 行×M 列）
- 图纸上以虚线标注板间分界线
- 导出时按单板分页导出（每页一块板的图纸），同时附一张全局总览图
- 每块分板图纸标注其在全局中的位置（如"第 2 行第 3 列"）

**业务规则：**
1. 拼接上限为 5×5 块板（最大约 145×145 或 290×290 取决于单板尺寸）
2. 超过上限时提示用户
3. 每块板的用量统计独立列出，方便分批采购和制作

**验收标准：**
- Given 用户选择 3×2 拼接 29×29 板，When 导出 PDF，Then 生成 7 页：1 页全局总览 + 6 页单板图纸，每页标注位置编号
- Given 用户在拼接图纸预览中，When 查看分界线，Then 虚线清晰标注板间边界

**优先级：** P0

---

#### 4.10 导出图纸

**用户故事：** 作为用户，我希望把做好的图纸导出为 PDF 或图片，方便打印或在平板上对照使用。

**功能描述：**
- 导出格式：PDF、PNG
- 导出内容包含：
  - 彩色图纸（每格填色 + 颜色编号）
  - 用量统计表（颜色编号、颜色名称、数量，按数量降序排列）
  - 原图缩略对比
- PDF 排版针对 A4 纸优化，确保打印清晰可读
- 多板拼接时分页导出（见 4.9）

**业务规则：**
1. 编号字体大小根据格子数量自适应（格子少时编号大，格子多时编号小）
2. 导出前可选择是否包含编号（纯色图纸 vs 带编号图纸）

**验收标准：**
- Given 用户完成 58×58 图纸编辑，When 导出 PDF，Then 生成包含彩色图纸页 + 用量统计页的 PDF 文件，A4 打印后编号清晰可读
- Given 用户选择"不包含编号"，When 导出 PNG，Then 生成纯色块图纸图片

**优先级：** P0

#### 4.11 分享链接与 Fork

**用户故事：** 作为用户，我希望将我的图纸分享给朋友，朋友可以直接用我的图纸作为起点进行修改。

**功能描述：**
- 用户点击"分享"按钮，生成唯一的分享链接
- 分享链接打开后的行为：

- Fork 产生的新项目独立于原项目，接收者可自由编辑
- 分享链接包含项目快照，原作者后续修改不影响已分享的链接内容

**业务规则：**
1. 每个项目可生成多个分享链接（每次分享生成新快照）
2. Fork 的项目占用接收者的槽位
3. 分享链接长期有效，不设过期时间
4. Web 落地页为轻量静态页，展示图纸预览图 + 基础信息（尺寸、色板品牌、颜色数量）

**验收标准：**

- Given 用户 A 分享后修改了自己的图纸，When B 再次打开之前的分享链接，Then B 看到的仍是 A 分享时的快照版本

#### 4.13 应用内购买（IAP）

**用户故事：** 作为用户，我希望通过购买解锁高级功能或立体拆件次数。

**功能描述：**
- 两类购买项：
  - **高级版（一次性买断）**：永久解锁无限槽位 + 抖动算法 + 高级色彩调整 + 去广告 + 赠送 V3 拆件 20 次
  - **V3 次数包（消耗型）**：所有用户（含免费用户）均可单独购买，提供三档：
    - 10 次包
    - 30 次包（阶梯降价）
    - 100 次包（阶梯降价）
- 通过 Apple App Store / Google Play Store 的应用内购买完成支付
- 购买状态与账号绑定（非设备绑定），换设备登录自动恢复
- 提供"恢复购买"按钮，供用户手动触发购买状态同步
- V3 剩余次数在立体拆件入口处显示

**业务规则：**
1. 高级版购买后立即生效，所有对应功能解锁
2. V3 次数包购买后次数累加到账户余额（高级版赠送的 20 次 + 额外购买的次数）
3. 每次成功生成一个立体拆件方案消耗 1 次（生成失败不扣次数）
4. 退款由 Apple/Google 平台处理，APP 端检测到高级版退款后自动降级为免费版（已消耗的 V3 次数不追回）
5. 付费页面清晰列出：高级版功能对比 + V3 次数包各档价格和单次均价

**验收标准：**
- Given 免费用户购买高级版，When 支付完成，Then 高级功能解锁、广告消失、V3 余额显示 20 次
- Given 免费用户（未购买高级版）购买 V3 30 次包，When 支付完成，Then V3 余额显示 30 次，但抖动算法等高级功能仍锁定
- Given 高级版用户已有 V3 余额 5 次，When 购买 10 次包，Then V3 余额变为 15 次
- Given 用户 V3 余额为 0，When 点击立体拆件，Then 提示"拆件次数已用完"并引导购买次数包
- Given 付费用户更换新手机，When 登录同一账号，Then 付费状态和 V3 余额自动恢复

**异常处理：**

| 异常场景 | 处理方式 | 提示文案 |
|---------|---------|---------|
| 支付过程中断（如切出 APP） | 下次进入 APP 时检查支付状态 | 若支付成功则静默解锁/到账 |
| 支付失败 | 提示重试 | "支付未完成，请重试" |
| 网络异常导致购买状态未同步 | 提供"恢复购买"入口 | "如已购买但功能未解锁，请点击恢复购买" |
| V3 生成过程中服务端异常 | 不扣次数，提示重试 | "生成失败，未扣除次数，请重试" |

**优先级：** P0

### V1.5 — 高级色彩（付费功能）

#### 4.15 抖动算法

**用户故事：** 作为付费用户，我希望启用抖动算法，让颜色过渡更自然，提升照片类图纸的还原度。

**功能描述：**
- 提供两种抖动算法供选择：
  - **Floyd-Steinberg**：经典误差扩散算法，色彩过渡自然，适合照片、渐变图
  - **Ordered Dithering（Bayer 矩阵）**：有序抖动，效果偏像素风格，与拼豆气质匹配
- 操作界面：
  - 抖动开关（默认关闭）
  - 算法选择（Floyd-Steinberg / Ordered Dithering）
  - 强度滑杆（0%~100%），控制抖动影响程度
- 调整时实时预览效果

**业务规则：**
1. 抖动可能增加使用的颜色种类数（因为会引入更多中间色）
2. 开启抖动后，在用量统计中额外提示"使用了 N 种颜色（比关闭抖动多 M 种）"
3. 抖动与"我的豆库"筛选兼容——抖动只在豆库内的颜色范围中进行

**验收标准：**
- Given 付费用户打开抖动开关选择 Floyd-Steinberg，When 调整强度滑杆从 0% 到 100%，Then 预览中色彩过渡逐渐变化且无卡顿
- Given 用户开启抖动并启用豆库筛选，When 查看图纸，Then 图纸中仅包含豆库内的颜色
- Given 免费用户点击抖动开关，When 检测到未付费，Then 提示"此功能为高级版专属"并引导购买

**优先级：** P1

### V2 — 智能拍照

#### 4.17 拍照智能抠图

### V3 — 立体拆件

#### 4.18 立体拼豆拆件系统

**用户故事：** 作为立体拼豆玩家，我希望上传一张物体/角色的图片，系统自动识别其立体结构并拆解为多片平面拼豆零件图纸，设计好拼接卡槽，我按图制作后能组装成立体作品。

**功能描述：**
- **图片上传与 3D 重建**：
  - 用户上传一张目标造型的参考图片（如角色正面图、玩具照片等）
  - 服务端通过单图 3D 重建模型（如 TripoSR / InstantMesh / TRELLIS）生成 3D 网格模型
  - 按所选拼豆尺寸（5mm / 2.6mm）进行体素化，每个体素对应 1 颗豆
  - 用户可调整整体尺寸（缩放体素化精度，影响最终成品大小和面片数量）
- **自动拆件**：
  - 算法自动确定最优切片方案（目标：最少面片数 + 最大结构稳定性）
  - 每个面片生成独立的平面拼豆图纸
  - 用户可预览 3D 视图，查看各面片的空间位置关系
- **卡槽自动设计**：
  - 在面片交汇处自动设计卡槽/插片连接
  - 根据拼豆物理特性计算卡槽尺寸（宽度 = 1 格，深度根据片材厚度匹配）
  - 卡槽位置用特殊标记显示（如灰色虚线格）
  - 卡槽位置可手动微调
- **面片编辑**：
  - 每个面片的颜色自动从原图映射，用户可独立编辑
  - 支持切换色板，所有面片重新匹配
  - 每个面片独立导出或全部打包导出
- **组装指引**：
  - 标注组装顺序（步骤 1→2→3...）
  - 每步说明哪两个面片如何拼接
  - 3D 示意图展示最终效果和各面片位置

**业务规则：**
1. 基于拼豆物理约束：
   - 最小卡槽宽度 = 1 颗豆宽（5mm 或 2.6mm 取决于所选系列）
   - 卡槽深度 = 面片高度的 1/3 至 1/2（确保结构稳定）
   - 两个卡槽间最小间距 ≥ 3 格（防止面片因卡槽过密而脆弱）
2. 结构稳定性校验：
   - 面片过大（单边 > 50 格）时警告"面片较大，建议增加支撑结构"
   - 底部支撑不足时警告"结构可能不稳定，建议增加底座面积"
   - 卡槽分布不均时警告并建议调整
3. 每次成功生成拆件方案消耗 1 次 V3 额度（生成失败不扣次数）
4. 3D 重建在服务端执行，需要网络连接
5. 单张图片的 3D 重建存在局限性（背面信息为推测），生成后提示用户检查并微调
6. 部署策略：初期接入第三方 3D 重建 API（如 Tripo3D），用户量增长后迁移至自部署模型降低成本

**验收标准：**
- Given 用户上传一张皮卡丘正面图并设置目标高度 30 格，When 服务端完成 3D 重建和拆件，Then 生成若干面片图纸（躯干前/后/左/右、耳朵×2、尾巴等），每个面片包含卡槽标记和颜色映射
- Given 拆件方案中某面片单边超过 50 格，When 系统校验结构，Then 弹出警告"该面片较大（60 格），建议增加中间支撑条"
- Given 用户完成所有面片编辑，When 查看组装指引，Then 显示带编号的步骤说明和 3D 示意图
- Given 用户 V3 余额为 0，When 点击生成拆件，Then 提示"拆件次数已用完"并引导购买次数包
- Given 3D 重建服务端异常，When 生成失败，Then 提示"生成失败，未扣除次数，请重试"

**异常处理：**

| 异常场景 | 处理方式 | 提示文案 |
|---------|---------|---------|
| 上传图片过于抽象/无法识别立体结构 | 提示用户更换图片 | "无法识别该图片的立体结构，建议上传物体/角色的清晰参考图" |
| 3D 重建结果面片过多（>20 片） | 警告复杂度并建议缩小尺寸 | "当前方案包含 N 个面片，组装难度较高。建议减小目标尺寸或选择更简单的造型" |
| 结构稳定性不足 | 弹出警告并提供建议 | "当前方案可能不稳定：[具体原因]。建议：[调整方案]" |
| 卡槽位置与用户手动编辑的图案冲突 | 卡槽优先，覆盖编辑 | "卡槽位置已覆盖该区域的颜色编辑" |
| 服务端超时（>30 秒） | 异步处理，完成后推送通知 | "正在生成中，完成后将通知您"（不扣次数直到成功） |

**优先级：** P2

## 五、业务流程

### 5.1 核心转换流程

```
开始
  → 用户登录
  → 新建项目（检查槽位 → 若已满，提示升级）
  → 选择板子规格（预设/自定义/拼接）
  → 上传图片（相册/拍照 → 自动预处理）
  → 调整图片（缩放/平移，实时预览）
  → 系统执行颜色匹配（基于所选色板 + 豆库筛选）
  → 预览图纸（切换显示模式）
  → 编辑调整（手动换色 / 高级色彩[付费]）
  → 导出（PDF/PNG）或 分享（生成链接）
  → 项目自动保存
结束
```

### 5.2 分享与 Fork 流程

```
用户 A 点击分享
  → 系统生成项目快照 + 唯一短链接
  → A 将链接发送到外部（微信/社交平台等）

用户 B 点击链接
  ├── 已安装 APP → Deep Link 打开 APP → 提示"Fork 到我的项目？"
  │     ├── 确认 → Fork 为 B 的新项目（占 B 槽位）→ B 可自由编辑
  │     └── 取消 → 仅预览不 Fork
  └── 未安装 APP → 浏览器打开 Web 落地页
        → 展示图纸预览 + 基础信息
        → "在 APP 中打开" 按钮 → 跳转应用商店
```

### 5.3 购买流程

```
【高级版购买】
用户点击付费功能入口（或主动进入高级版页面）
  → 展示免费版 vs 高级版功能对比
  → 用户点击购买高级版
  → 调用 Apple IAP / Google Play Billing
  → 支付成功 → 解锁所有高级功能 + 去除广告 + V3 额度 +20
  → 支付失败 → 提示重试

【V3 次数包购买】
用户点击立体拆件（V3 余额为 0）或主动进入次数包页面
  → 展示三档次数包（10 次 / 30 次 / 100 次）及单次均价
  → 用户选择档位并购买
  → 调用 Apple IAP / Google Play Billing
  → 支付成功 → V3 余额累加
  → 支付失败 → 提示重试
```

### 5.4 账号合并流程

```
用户用方式 B 登录（如微信）
  → 系统检测到方式 B 关联的手机号/邮箱已有账号 A
  → 提示"检测到已有账号，是否合并？"
  ├── 确认合并 → 项目数据合入（保留双方所有项目）→ 方式 B 成为账号 A 的新登录方式
  └── 取消 → 创建独立新账号（方式 B 不与账号 A 关联）
```

### 5.5 项目状态流转

| 当前状态 | 触发事件 | 目标状态 |
|---------|---------|---------|
| 无 | 新建项目 | 编辑中 |
| 编辑中 | 用户退出编辑 | 已保存 |
| 已保存 | 用户重新打开 | 编辑中 |
| 编辑中/已保存 | 用户删除 | 已删除 |
| 已保存 | 用户分享 | 已保存（生成快照，状态不变） |

## 六、数据需求

### 6.1 核心数据对象

## 十、风险与约束

### 10.1 已知风险

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|---------|
| 色板数据不准确（RGB 值与实际豆子颜色有偏差） | 用户按图纸拼出来的颜色与预期不符，信任度下降 | 中 | 从品牌官方渠道获取色值；引入社区反馈纠错机制；允许用户微调单色 RGB |
| 各品牌色号数据变更/新品上市 | 色板数据过时 | 中 | 定期更新色板数据（随 APP 版本更新）；预留热更新色板数据能力 |
| Apple/Google 审核拒绝 | 上线延迟 | 低 | 提前了解审核指南，尤其 IAP 相关规则 |
| 分享链接被滥用（传播不当内容） | 品牌风险 | 低 | 分享内容仅为像素图纸（难以传播不当内容）；预留举报/下线能力 |
| V3 立体拆件结构稳定性算法不成熟 | 用户拼完塌了，体验极差 | 中 | 先从简单结构（长方体）做起；保守的稳定性阈值；明确标注"实验功能" |

### 10.2 技术约束

- 颜色匹配算法（CIEDE2000）计算量较大，需要在移动端做性能优化（可考虑预计算查找表）
- 端侧抠图模型（V2）需要控制模型大小，避免 APP 包体积过大
- 分享 Web 落地页需要额外的前端部署和域名
- V3 3D 重建需要 GPU 服务器支持：
  - 初期方案：接入第三方 3D 重建 API（如 Tripo3D），零硬件投入，快速验证
  - 中期方案：云 GPU 按需实例（AWS g4dn.xlarge / T4 16GB），自部署 TripoSR，单次成本降至几分钱
  - 长期方案：日请求量稳定后（500+/天）考虑自建 GPU 服务器
- 单张图片 3D 重建的局限性：背面信息为模型推测，复杂造型（多肢体角色）效果不如简单造型，需在产品层面做预期管理

### 术语表

| 术语 | 定义 |
|------|------|
| 拼豆（Perler Beads / Fuse Beads） | 小型塑料珠子，排列在模板板上后用熨斗热熔固定成型的手工艺品材料 |
| 色板（Color Palette） | 某品牌/系列拼豆所有可用颜色的集合，包含颜色编号和对应 RGB 值 |
| 豆库（Bead Inventory） | 用户实际拥有的拼豆颜色集合 |
| 板子（Pegboard） | 用于排列拼豆的带孔模板板，有固定的行列格数 |
| 抖动（Dithering） | 一种通过在相邻像素间交错使用不同颜色来模拟中间色调的图像处理算法 |
| 卡槽 / 插片 | 立体拼豆中用于连接两个平面零件的缺口/凸出结构 |
| Fork | 复制他人分享的项目为自己的独立副本，可自由编辑不影响原作者 |
| CIEDE2000 | 在 CIELAB 色彩空间中计算两个颜色差异的标准公式，比简单的 RGB 欧氏距离更符合人眼感知 |
| IAP（In-App Purchase） | 应用内购买，通过 Apple App Store 或 Google Play 完成的支付 |
