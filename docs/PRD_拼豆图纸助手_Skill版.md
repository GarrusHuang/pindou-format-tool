## 二、产品概述

### 2.1 背景

将原计划的 Web 应用简化为 Claude Code Skill，聚焦核心业务能力：图片→拼豆图纸转换 + 立体拆件。去掉所有产品化包装（登录、支付、广告、后台管理等），用最轻量的方式实现全部核心功能。

### 2.2 产品形态

Claude Code Skill —— 用户在 Claude Code 中通过自然语言交互，输入图片和参数，输出拼豆图纸文件。

### 2.3 技术原则

1. **能用代码做的直接用代码做** —— 图片处理、颜色匹配、抖动算法、导出等全部用 Python 实现
2. **代码做不了的用 LLM** —— 立体拆件的 3D 结构分析用 Claude 视觉能力，智能抠图用 rembg 库
3. **不依赖外部付费 API** —— 除非用户主动配置

## 四、功能需求详述

### 4.1 图片加载与预处理

**输入：** 用户提供图片路径

**处理：**
- 支持格式：PNG、JPG/JPEG、BMP、WebP
- 过大图片（超过 4096×4096）自动缩小
- 过小图片（<50×50）警告但允许继续
- 检测透明通道：有透明区域的，透明部分标记为"不放豆"

**输出：** 预处理后的图片对象，供后续流程使用

---

### 4.2 板子规格选择

**交互方式：** Skill 引导用户选择或直接从参数获取

**支持的规格：**
- 预设：29×29（小板）、58×58（大板）
- 自定义：用户指定宽×高格数，上限 200×200
- 多板拼接：N行×M列，上限 5×5

**默认值：** 58×58，图片自适应填充

---

### 4.3 像素化

**处理：** 将预处理后的图片缩放到板子网格尺寸（如 58×58 像素）

**算法：** Pillow 的 LANCZOS 重采样（缩小时效果最好）

**输出：** 每个像素 = 一个格子的颜色

---

### 4.4 颜色匹配

**核心算法：** CIEDE2000 色差公式（在 CIELAB 色彩空间中计算）

**处理流程：**
1. 将图片每个像素的 RGB 转换为 CIELAB
2. 将色板中每个颜色的 RGB 也转换为 CIELAB
3. 对每个像素，找到色板中 CIEDE2000 距离最小的颜色
4. 如果启用了豆库筛选，只在用户拥有的颜色中匹配

**性能优化：**
- 色板 CIELAB 值预计算并缓存
- 使用 NumPy 向量化计算，避免逐像素 Python 循环
- 58×58 = 3364 像素 × ~200 色板颜色，应在 1 秒内完成

---

### 4.5 多品牌色板

**内置色板数据（JSON 格式）：**

```json
{
  "brand": "Artkal",
  "series": "H (5mm 硬豆)",
  "colors": [
    {"code": "H1", "name": "白色", "rgb": [255, 255, 255], "discontinued": false},
    {"code": "H2", "name": "奶白", "rgb": [245, 240, 230], "discontinued": false}
  ]
}
```

**支持品牌：**
- Artkal：H 系列（5mm 硬豆）、S 系列（5mm 软豆）、C 系列（2.6mm）
- Hama：基础色、扩展色
- Perler：标准色
- 国产品牌：根据数据可得性补充

**色板数据来源：** 需从品牌官方渠道、爱好者社区或实物测色获取 RGB 值。数据文件存放在 skill 的 `data/palettes/` 目录下。

---

### 4.6 我的豆库

**功能：** 用户指定"我有哪些颜色"，匹配时只用这些颜色。

**交互方式：**
- 默认使用色板全部颜色
- 用户可以说"我没有 H15、H23、H40 这几个颜色"，Skill 将其排除
- 或者说"我只有这些颜色：H1-H50"
- 豆库配置可保存为文件，下次复用

**业务规则：**
- 豆库中颜色 < 10 种时警告"颜色过少，效果可能不理想"
- 排除的颜色不参与自动匹配，但用户可以在手动调整时指定使用

---

### 4.7 抖动算法

**两种算法：**

**Floyd-Steinberg（误差扩散）：**
- 对每个像素，计算匹配色与原色的误差
- 将误差按比例扩散给相邻像素（右7/16、左下3/16、下5/16、右下1/16）
- 效果：色彩过渡自然，适合照片

**Ordered Dithering（Bayer 矩阵）：**
- 使用 8×8 Bayer 矩阵作为阈值图
- 每个像素根据其位置对应的阈值调整亮度后再匹配
- 效果：规律性图案，偏像素风，与拼豆气质匹配

**参数：**
- 开关：开/关（默认关）
- 算法选择：Floyd-Steinberg / Ordered
- 强度：0%-100%（通过混合原始匹配结果和抖动结果实现）

**与豆库兼容：** 抖动只在可用颜色范围内进行。

---

### 4.8 高级色彩调整

**批量颜色替换：**
- 输入：将颜色 A 替换为颜色 B
- 处理：图纸中所有颜色 A 的格子变为颜色 B
- 用量统计实时更新

**色调偏移：**
- 输入：偏移方向（偏暖/偏冷/偏亮/偏暗）和强度
- 处理：对图纸中每个格子的原始颜色进行 HSL 调整，然后重新匹配色板
- 会清空之前的手动编辑

---

### 4.9 网格辅助线与编号

**绘制在导出图纸上：**
- 每 N 格（默认 10，可选 5/10）绘制加粗参考线
- 图纸边缘标注行号和列号
- 每个格子内绘制颜色编号文字（字体大小自适应格子尺寸）

**显示模式（导出时可选）：**
- 色块模式：每格填充纯色
- 圆点模式：每格中心画圆点，模拟真实拼豆效果
- 编号模式：每格显示颜色编号（最实用的对照模式）
- 色块+编号：填色并叠加编号

---

### 4.10 用量统计

**输出内容：**
- 按颜色编号列出每种颜色需要的豆子数量
- 按数量降序排列
- 总计豆子数量
- 使用的颜色种类数
- 如果有空格（透明/不放豆），单独标注空格数量

**输出格式：**
- 终端表格打印
- 同时写入导出 PDF 的统计页

**多板拼接时：** 提供总统计 + 每块板的独立统计

---

### 4.11 多板拼接

**处理流程：**
1. 根据拼接设置（N行×M列×单板尺寸）确定总图纸尺寸
2. 图片缩放到总尺寸
3. 在板间边界绘制虚线分界线
4. 导出时：1 张全局总览图 + N×M 张单板图纸
5. 每张单板图纸标注位置编号（如"第2行第3列"）

---

### 4.12 导出 PNG

**输出文件：**
- `{项目名}_全局.png` — 完整图纸（带辅助线和编号）
- `{项目名}_圆点.png` — 圆点模式预览
- `{项目名}_板_{行}_{列}.png` — 各单板图纸（多板拼接时）

**图片参数：**
- 每格像素大小：可配置（默认 20px/格）
- 格线宽度：1px（普通线）、2px（辅助参考线）

---

### 4.13 导出 PDF

**输出文件：** `{项目名}_图纸.pdf`

**页面内容：**
1. 封面页：项目名称、原图缩略、板子规格、色板品牌
2. 全局总览页：缩小版完整图纸
3. 单板图纸页（每板一页）：带编号的彩色图纸，A4 排版优化
4. 用量统计页：颜色用量表格

**排版：** A4 纵向，边距适当，编号字体清晰可读

---

### 4.14 智能抠图

**功能：** 自动去除图片背景，只保留主体。

**实现：** 使用 `rembg` 库（基于 U²-Net 模型，本地运行，不依赖外部 API）

**处理流程：**
1. 用户提供图片，指示需要抠图
2. rembg 处理后输出带透明通道的 PNG
3. 透明区域在后续转换中标记为"不放豆"
4. 用户可选择是否使用抠图结果

**首次使用时：** rembg 会自动下载模型文件（约 170MB），后续使用无需重复下载。

**交互：**
- 用户说"帮我去掉背景"或"只保留主体"时触发
- 处理后输出抠图前后对比预览
- 用户确认后进入正式转换流程

---

### 4.15 立体拆件

**功能：** 用户上传一张目标物体/角色的图片，系统分析其立体结构并拆解为多个平面拼豆零件图纸，设计卡槽连接。

**实现方式：** Claude 视觉分析（理解 3D 结构）+ Python 代码（生成面片图纸和卡槽）

**处理流程：**

**第一步：结构分析（LLM）**
- Claude 读取用户上传的参考图片
- 分析物体的立体结构，确定需要拆成哪些面片
- 输出结构化的拆件方案：
  ```json
  {
    "name": "皮卡丘",
    "panels": [
      {"id": "body_front", "name": "躯干正面", "width": 30, "height": 40, "connects_to": ["body_left", "body_right", "body_back"]},
      {"id": "body_back", "name": "躯干背面", "width": 30, "height": 40, "connects_to": ["body_left", "body_right"]},
      {"id": "body_left", "name": "躯干左侧", "width": 15, "height": 40, "connects_to": ["body_front", "body_back"]},
      {"id": "ear_left", "name": "左耳", "width": 8, "height": 20, "connects_to": ["body_front"]}
    ],
    "assembly_order": ["body_front", "body_left", "body_back", "body_right", "ear_left", "ear_right", "tail"]
  }
  ```
- 用户确认或调整方案

**第二步：面片图纸生成（代码）**
- 根据拆件方案，Claude 描述每个面片的颜色布局（哪个区域什么颜色）
- 代码生成每个面片的像素网格
- 执行颜色匹配（与平面图纸相同流程）
- 在面片交汇处自动设计卡槽

**第三步：卡槽设计（代码）**
- 根据拼豆物理约束自动计算：
  - 卡槽宽度 = 1 格
  - 卡槽深度 = 面片高度的 1/3 至 1/2
  - 卡槽间最小间距 ≥ 3 格
- 在面片图纸上标记卡槽位置（灰色虚线格）
- 结构稳定性校验：
  - 面片过大（单边 > 50 格）→ 警告
  - 底部支撑不足 → 警告
  - 卡槽分布不均 → 警告并建议调整

**第四步：组装指引（LLM + 代码）**
- Claude 生成组装步骤的文字说明
- 代码生成每个步骤的示意图
- 输出完整的组装指引文档

**输出：**
- 每个面片的 PNG 图纸（带卡槽标记和编号）
- 组装指引（文字 + 示意图）
- 各面片用量统计
- 全部打包在一个目录下

## 五、交互流程

### 5.1 标准转换流程

```
用户：/pindou 把这张图转成拼豆图纸 [图片路径]

Skill：
  1. 读取图片，显示基本信息（尺寸、格式）
  2. 询问参数（可一次性指定，也可逐步引导）：
     - 板子规格？（默认 58×58）
     - 色板品牌？（默认 Artkal H 系列）
     - 要不要抖动？（默认关闭）
     - 需要抠图吗？（根据图片判断是否建议）
  3. 执行处理：像素化 → 颜色匹配 → 抖动（如开启）
  4. 输出预览图 + 用量统计
  5. 询问是否需要调整（换色、色调偏移等）
  6. 导出最终图纸（PNG + PDF）
```

### 5.2 快捷模式

用户可以一句话完成：
```
用户：/pindou 转换 ./pikachu.png 29×29 Artkal-H 抖动Floyd50%
→ 直接出结果，不用逐步问答
```

### 5.3 立体拆件流程

```
用户：/pindou 立体拆件 ./pikachu_ref.png 高度30格

Skill：
  1. Claude 分析图片，输出拆件方案
  2. 用户确认/调整
  3. Claude 描述每个面片的颜色布局
  4. 代码生成面片图纸 + 卡槽
  5. 结构校验 + 组装指引
  6. 导出全套文件
```
